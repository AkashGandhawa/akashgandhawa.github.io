Part 1: Advanced React Theory & Architecture

To succeed in a non-basic assessment, you must demonstrate an understanding of why you are using specific tools, not just how.

1. Component Architecture & Custom Hooks

In professional applications, data-fetching logic is abstracted away from UI components. We use custom hooks (like useFetch) to handle the fetch lifecycle, keeping the components strictly focused on rendering the UI.

2. Complex State Management

For simple toggles, useState is fine. If state involves multiple sub-values or the next state depends heavily on the previous state, useReducer is the standard. It centralizes state transition logic outside the component render cycle.

3. Routing (React Router)

Modern single-page applications (SPAs) use libraries like react-router-dom to intercept the URL change and dynamically swap out the React components being rendered, preserving the application's state without a full page reload.

4. Backend Interaction & API Consumption (Required Focus)

Even without building a backend, you must handle the realities of network requests in the frontend:

  • Asynchronous JavaScript: Use async/await and Promises to handle data fetching without freezing the UI.
  • Tri-State UI Management: Every API call has three possible states: Loading, Error, and Success.
  • Lifecycle and Cleanup: Use an AbortController in your useEffect cleanup function to cancel requests if the component unmounts prematurely, preventing memory leaks.
Side Question: What is the "Dependency Array" in useEffect?
  • Omitted useEffect(() => {...}): Runs on every single render. Usually causes infinite loops.
  • Empty []: Runs exactly once when the component mounts.
  • Populated [url, id]: Runs only when url or id changes between renders.
Side Question: Explain "Prop Drilling" and its solution.

Explanation: Passing data from a high-level component down through multiple intermediate components that don't need it, just to reach a deeply nested child.
Solution: Use the Context API (createContext and useContext) to "teleport" data, or use a state manager like Redux.

Part 2: Advanced Git Theory & Repository Management

1. Branching Strategy

Never work directly on the main branch. main reflects production code. develop is the integration branch. feature/* branches are created for specific tasks and merged back into develop.

2. Rebasing vs. Merging

  • Merge: Ties two branches together with a "merge commit." Non-destructive but creates a web-like history.
  • Rebase: Moves the feature branch to begin on the tip of the target branch. Rewrites history for a clean, linear commit history.
Side Question: How do you resolve a Git Merge Conflict?
  1. Run git status to identify unmerged files.
  2. Open the file and look for markers: <<<<<<< HEAD, =======, and >>>>>>> branch.
  3. Manually edit the code to the desired state and delete markers.
  4. Stage the file: git add <filename> and complete: git commit or git rebase --continue.

Step 2: The API Hook (Backend Interaction)

Create src/hooks/useFetch.js. This handles async logic, tri-state UI management, and cleanup.

import { useState, useEffect } from 'react';

export const useFetch = (url) => {
    const [data, setData] = useState(null);       // State 1: Success
    const [loading, setLoading] = useState(true); // State 2: Loading
    const [error, setError] = useState(null);     // State 3: Error

    useEffect(() => {
        const abortController = new AbortController(); 

        const fetchData = async () => {
            setLoading(true);
            try {
                const response = await fetch(url, { signal: abortController.signal });
                if (!response.ok) throw new Error(`HTTP Error: ${response.status}`);
                const json = await response.json();
                setData(json);
            } catch (err) {
                if (err.name !== 'AbortError') setError(err.message);
            } finally {
                setLoading(false);
            }
        };

        fetchData();
        return () => abortController.abort(); // Cleanup on unmount
    }, [url]);

    return { data, loading, error };
};

Step 4: The Components (UI State Handling)

Home Page (src/pages/Home.jsx)

import { Link } from 'react-router-dom';
import { useFetch } from '../hooks/useFetch';

export default function Home() {
    const { data: users, loading, error } = useFetch('https://jsonplaceholder.typicode.com/users');

    if (loading) return <div>Loading user database...</div>;
    if (error) return <div style={{ color: 'red' }}>Failed to load: {error}</div>;

    return (
        <div>
            <h2>Employee Directory</h2>
            <ul className="directory-list">
                {users.map((user) => (
                    <li key={user.id} className="directory-item" style={{ borderLeft: `5px solid ${user.id % 2 === 0 ? '#28a745' : '#007bff'}` }}>
                        <strong>{user.name}</strong> 
                        <Link to={`/user/${user.id}`} className="btn-link">View Details</Link>
                    </li>
                ))}
            </ul>
        </div>
    );
}

Details Page (src/pages/UserDetails.jsx)

import { useParams, Link } from 'react-router-dom';
import { useFetch } from '../hooks/useFetch';

export default function UserDetails() {
    const { id } = useParams();
    const { data: user, loading, error } = useFetch(`https://jsonplaceholder.typicode.com/users/${id}`);

    if (loading) return <div>Fetching profile details...</div>;
    if (error) return <div style={{ color: 'red' }}>Error: {error}</div>;

    return (
        <div className="profile-card">
            <h2>{user.name}'s Profile</h2>
            <div style={{ margin: '20px 0', color: '#555' }}>
                <p><strong>Email:</strong> {user.email}</p>
                <p><strong>Company:</strong> {user.company.name}</p>
            </div>
            <Link to="/" className="btn-link">&larr; Back to Directory</Link>
        </div>
    );
}
